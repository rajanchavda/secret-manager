The Threat Model

Why traditional .env files fail with AI agents

AI coding assistants inspect your project files, run terminal commands, and ingest directory trees. Here is why existing secret managers leave you exposed.

AI Context Ingestion

Tools like Cursor, Claude Desktop, and Copilot automatically parse workspace files. When an agent runs cat .env or ripgrep to debug an error, production Stripe keys and database connection strings get copied straight into model prompt transcripts.

The Disk Decryption Trap

If a secret utility decrypts your credentials into plaintext on your disk while your dev server runs (e.g. npm run dev), the AI agent can read those secrets at any millisecond while you program. A secret on disk is never safe from a background tool.

The Decoy + Hardware Vault

sec keeps your real credentials inside Apple Silicon's hardware Secure Enclave. The file on disk is replaced by a safe decoy file (API_KEY=locked_by_sec), while real secrets are injected strictly into process RAM upon a physical Touch ID tap.

Architecture

Three steps. Zero plaintext on disk.

Keep linters, syntax highlighters, and static tools happy with decoy placeholders, while handing real keys directly to your dev server behind closed doors.

Step 01

Lock with Touch ID

Run sec lock .env or right-click in Finder. Encrypts real secrets into .env.vault with AES-256-GCM. Replaces disk .env with sanitized dummy placeholders.

$ sec lock .env
Step 02

Run with Biometrics

Prefix any development command with sec (e.g. sec npm run dev, sec cargo run). Touch ID prompts once for your physical fingerprint tap.

$ sec npm run dev
Step 03

Pure In-Memory Injection

Secrets are injected directly into child process RAM (process.env). Plaintext never touches your storage drive, and secrets self-destruct as soon as the process exits.

FAQ

Frequently Asked Questions

Everything you need to know about Apple biometrics, memory safety, and threat boundaries.

Does it work when my MacBook lid is closed (clamshell mode)?

Yes. Apple's LocalAuthentication framework automatically falls back to an Apple Watch biometric tap, Touch ID on an external Apple Magic Keyboard, or your Mac login password if the MacBook display lid is closed.

Can an AI coding agent run `sec view` to read my secrets?

No. Every invocation of sec (including sec view and sec run) triggers a physical macOS LocalAuthentication prompt. Without your finger physically touching the Mac's sensor, the vault will not unlock.

How does stealth loading defeat `ps -E` inspection?

On Unix and Darwin, running processes can have their environment queried by other processes via ps -E or sysctl KERN_PROCARGS2. For Node.js and Python development, sec uses ephemeral preload loader hooks that inject credentials straight into the language runtime memory, completely bypassing public command-line arguments.

What happens to my IDE and linters when `.env` is locked?

When sec lock runs, it inspects your .env keys and replaces their values with locked_by_sec. This keeps the file syntactically valid. ESLint, Prisma schema validators, TypeScript types, and dotenv parsers continue to function without crashing.

Is `.env.vault` committed to Git?

No. sec lock automatically adds *.vault and .env.vault to your project's .gitignore. Your secrets remain strictly hardware-encrypted on your local Mac.

Does `sec` support monorepos with nested packages?

Yes! If your root repository contains .env.vault and you execute sec npm run dev inside a nested subpackage (e.g. apps/web or packages/api), sec traverses up the folder tree, discovers the root vault, and injects the secrets seamlessly.

Is `sec` free and open source?

Yes, 100%. sec is released under the permissive MIT license. There are no subscriptions, no accounts, and no paid tiers.
